# Talshift

Talshift is a React single-page app served by an Express HTTP server. The backend exposes authentication, profile, and workspace APIs and connects to PostgreSQL through `pg`.

## Requirements

- Node.js 20.19 or newer (Node.js 22 LTS recommended) and npm
- A reachable PostgreSQL database

## Configure PostgreSQL

The PostgreSQL server must have the `pgvector` extension installed; backend startup enables it and creates the search tables and vector index.

Set `DATABASE_URL` in the shell where the backend will run. For PowerShell:

```powershell
$env:DATABASE_URL = "postgres://postgres:password@localhost:5432/talshift"
```

For Command Prompt:

```bat
set DATABASE_URL=postgres://postgres:password@localhost:5432/talshift
```

Set `GEMINI_API_KEY` in the backend environment for student talent, search-attribute extraction, and resume parsing (PDF uploads during onboarding and from the student Profile page; the file is sent to Gemini and not stored). The backend keeps the key private and uses the `gemini-3.8-flash` model by default; set `GEMINI_MODEL` to another model enabled for your API key.

Set `OPENAI_API_KEY` to enable attribute embeddings. The default model is `text-embedding-3-small` with 1536 dimensions; `OPENAI_EMBEDDING_MODEL` can select another OpenAI model that supports the same dimensions. Search results also require a calibrated `SEARCH_HARD_GATE_COSINE_THRESHOLD` between `-1` and `1`; search returns an explicit configuration error until it is set. Do not treat the displayed similarity as a calibrated probability.

Project credibility verification reads students' public repositories and commits from the GitHub API, across up to five GitHub accounts per student, and uses `GEMINI_API_KEY` for the reviewer notes. Besides repositories each account owns, it finds repositories the student contributed commits to through GitHub's commit search, which has a separate limit of 10 searches per minute without a token. Each extra account adds requests for every matched repository. Unauthenticated GitHub requests are limited to 60 per hour per server IP; set `GITHUB_TOKEN` to a fine-grained token with public read-only access to raise that limit. Verification results are cleared whenever a student edits their profile.

Search only uses attributes generated by the currently configured `GEMINI_MODEL`. After changing that model, regenerate student talent and re-index professional summaries and postings before searching.

Use credentials appropriate for your local database; do not commit them.

## Development

Start the backend from `backend/` in one terminal:

```powershell
cd backend
npm install
npm run dev
```

Then, in another terminal, start Vite:

```sh
cd frontend
npm install
npm run dev
```

Open the URL it prints; requests to `/api/*` are proxied to the backend at `http://127.0.0.1:3000`.

## Production Build

Build the frontend, then build and start the backend:

```sh
cd frontend
npm ci
npm run build
cd ../backend
npm ci
npm run build
npm start
```

The backend serves `frontend/dist` by default. Set `FRONTEND_DIST` to use another build directory, or `PORT` to change the HTTP port.

## Checks

```sh
cd frontend
npm run typecheck
npm run build
cd ../backend
npm run typecheck
npm run build
```

`GET /api/health` runs `SELECT 1` and returns `{"status":"ok"}` when the database is available, or HTTP 503 when it is not. Authentication, profiles, postings, search attributes, and cached embeddings are stored in PostgreSQL. Student and professional profiles are discoverable by default; published job postings are searchable separately. Unknown API routes return a JSON 404.
